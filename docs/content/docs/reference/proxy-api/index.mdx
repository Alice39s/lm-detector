---
title: 代理 API
description: 转发代理的 HTTP 接口，由 worker/openapi.json 描述，本站代理与自建 Worker 共用同一份约定。
---

转发代理只有一个路径 `/api/proxy`：`GET` 做健康检查，`POST` 转发 API 请求，`OPTIONS` 回应浏览器的 CORS 预检。本站代理只接受同源调用；自建 Worker 还接受 `ALLOWED_ORIGINS` 中的页面，并且在任何路径上都给出相同的回答。

<Cards>
  <Card title="Health check" href="./checkProxy.mdx">`GET /api/proxy`：确认地址是 Fingerpoint 代理。</Card>
  <Card title="Relay an API request" href="./relayRequest.mdx">`POST /api/proxy`：用你的密钥转发请求，原样流式返回。</Card>
</Cards>

`OPTIONS` 预检由浏览器在跨域 `POST` 前自动发送，允许的 origin 得到 204 和 `Access-Control-Allow-*` 头，其余得到不带 CORS 头的 403。

下面的页面由 `worker/openapi.json` 生成；修改这份约定后，在 `docs/` 中运行 `bun run openapi` 重新生成。页面中的 Playground 会从你的浏览器直接发出请求：在本站的文档中，它经同源 `/api/proxy` 把你填写的密钥和请求转发给上游，与网页检测经本站代理时相同。

<Callout type="warn">
  Playground 发送的是真实请求，会消耗上游额度。不要在不信任的页面上填写密钥。
</Callout>
