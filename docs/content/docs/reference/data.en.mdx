`data/` holds the official reference samples, the derived fingerprint bank, the frozen detector parameters, the fixed sampling challenges, and the tokenizer bank of the tokenizer probe.

```files
data
├── unified_reference.jsonl
├── unified_bank.json
├── shared_detector.json
├── enrollment-suite.json
├── tokenizer_bank.json
├── import_manifest.json
├── archive
└── collections
```

| File | Content |
| --- | --- |
| `unified_reference.jsonl` | Reference batches. Each line holds one version-1 batch: the model, channel, and call settings are shared, and the answers are in the `samples` array |
| `unified_bank.json` | Statistics derived from the reference batches |
| `shared_detector.json` | Frozen ranker, verifier, and calibration parameters, bound to the reference data by SHA-256 |
| `enrollment-suite.json` | The 36 fixed sampling challenges. This file is sampling input, not reference answers |
| `tokenizer_bank.json` | Tokenizer bank: probe texts, per-class counts, and model mappings for the tokenizer probe |
| `import_manifest.json` | Historical manifest. It does not reflect the current counts |
| `archive/` | Historical batches retired from the reference bank |
| `collections/` | Sampling requests, attempts, and provenance checks |

`archive/` and `collections/` are not used for scoring and are not copied into the public data of the website. For the fields of batches and samples, see [Sampling and resuming](../cli/sampling.mdx#batch-format).

## Maintenance rules

- `fpd sample`, `fpd enroll DIR`, and `fpd retrain --data-dir DIR` can all run outside the repository. Enrollment validates complete batches and raw evidence, deduplicates by model, channel, condition, challenge, and text, and rebuilds the derived bank. Retraining fits the verifier and confidence offline from the target reference bank. If nested calibration fails, `shared_detector.json` is not replaced. Training evidence is saved in `.training/`.
- The data bundled with the CLI is read-only. The maintenance destination must be specified explicitly, or confirmed after the CLI detects this repository during interactive enrollment.
- The fixed evaluation set must not be added to the reference bank, the model centroids, or the calibration.
- The website build writes redacted data to `web/public/data/`. That directory is a build output and must not be maintained as a second official bank.

## Tokenizer bank

`tokenizer_bank.json` is generated offline from 290 open tokenizers by `token-fp export-api-bank` of the tokenizer archive tool llm-tokenizer-fingerprint. It is independent of the reference samples. An update replaces the whole file directly and does not go through `fpd enroll`.

| Field | Content |
| --- | --- |
| `schema` | Always `tokenizer-bank-v1` |
| `source` | Generating tool, tokenizer count, and candidate text count. `archive_manifest_sha256` records the hash of the archive manifest used, and `excluded` lists the repositories that were not exported because their archived files are untrusted, with the reasons |
| `wrapper` | The fixed prefix and suffix of every request: `prefix` and `suffix` |
| `probes` | ID, category, and text of each probe text |
| `classes` | Lab, series, members, and aliases of each tokenizer class, and its count difference for each probe text in `counts`. When members disagree, `alternatives` lists their values separately |
| `api_models` | Mapping from vendor models to tokenizer classes. A `class` of `null` means the vendor has not published its tokenizer |

Tokenizer classes are grouped by authoring lab and series. Tokenizers with identical counts form one class, and classes of one lineage that differ on only a few texts are merged. For the full list of classes, see [How the tokenizer probe works](../principles/tokenizer.mdx#classes).
