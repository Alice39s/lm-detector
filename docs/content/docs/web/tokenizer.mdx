分词器是模型把文本切成 token 的规则。同一家厂商的模型通常共用一种分词器，所以知道上游（你填写的接口背后的服务）用的是哪一种，就能帮数字指纹分清 GPT、Qwen、DeepSeek 等家族，也能发现声称 `gpt-5` 却用着 Qwen 分词器的渠道。

分词器探测是 API 模式的一部分，默认开启。代价是取样时多发约 12 个短请求，最多 22 个；按次计费的接口会多计这些请求。这些请求沿用你设置的推理强度（Messages 协议除外），Messages 以外的协议不限制输出，推理模型上会多花一些 token。在 API 配置里关闭“分词器探测”，检测就只用数字指纹。手动模式没有接口可问，只用数字指纹。

## 一次检测里发生什么

### 开始取样 [step]

点击“开始取样”后，三张样本卡下方出现“分词器探测”卡。它显示已完成的请求数和暂时领先的分词器。每个请求只要求模型回复 OK，页面读取接口返回的用量（`usage`）里的输入 token 数。

“并行请求”开启时，分词器探测每批发 4 个请求；关闭后逐个发送，耗时更长。

### 等待探测完成 [step]

三条样本完成时，如果分词器探测还没结束，计算状态行显示“正在完成分词器探测…”，操作栏的“停止探测”可以提前结束，页面用已收到的计数计算。

### 查看结果 [step]

结果出现后，样本摘要条的第四项“分词器”显示判定出的分词器，点开可以看详情。第一候选的家族名旁有一个徽标，说明它的分词器与实测是否一致。

## 结果怎么读

排名的置信度已经并入分词器结果，排名说明会写“按并入分词器结果后的置信度排序”。并入时，分词器结果最多把两个候选的概率比改变约 600 倍，数字指纹的差距更大时，两者的顺序不变，方法见[原理](../principles/tokenizer.mdx#fusion)。

第一候选旁的徽标：

| 徽标 | 含义 |
| --- | --- |
| 分词器一致 | 该候选使用的分词器与实测相同 |
| 分词器不符 | 实测的分词器不是该候选使用的 |
| 分词器待定 | 计数还不足以判断 |
| 分词器未知 | 本工具不知道该候选使用哪种分词器，分词器结果不影响它 |

结果区还可能出现三种提示：

- 分词器结果改变了第一候选时，写明数字分布最接近的是哪个候选。
- 所填模型与实测的分词器不一致时，用红色提示写明该模型应使用的分词器。
- 没有取得分词器结果时，排名说明下方写明原因，并说明本次只使用数字指纹。

## 分词器详情

详情左侧是判定、置信度和候选分词器，右侧是请求记录。判定只有三种：

| 判定 | 含义 |
| --- | --- |
| 完全一致 | 几乎所有测试文本的计数都与某一类已收录的分词器吻合，允许少数偏差 |
| 未收录 · 最接近 | 与某一类相近，但相当一部分测试文本的计数不同，可能是它的衍生或扩展版本 |
| 未收录的分词器 | 与所有已收录的类都无关 |

“类”指计数方式几乎相同的一组开源分词器。本工具收录 62 类，见[已收录的分词器](../principles/tokenizer.mdx#classes)。

候选列表显示前 6 类的置信度，最后一行固定为“未收录的分词器”。请求记录的每一行是一条测试文本，或只含固定前后缀的对照请求（显示为“对照请求（不含测试文本）”），右侧是输入 token 数和比对照请求多出的 token 数。

详情底部有三个折叠项：这一类包含的开源分词器、每条测试文本的计数表、如何理解探测结果。

## 与所填模型核对

所填模型名会与[厂商型号映射](../principles/tokenizer.mdx#api-models)比对：

| 结果 | 含义 |
| --- | --- |
| 一致 | 实测的分词器与该模型使用的相同 |
| 不一致 | 例如声称 `gpt-5` 却测得 Qwen 的分词器 |
| 还不能确定 | 计数还没有集中到某一类 |
| 无法判断 | 本工具还不知道该模型使用哪种分词器 |

Claude、Grok 等厂商没有公开分词器：测得“未收录的分词器”算作一致，测得任何已收录的类算作不一致。

<Callout type="warn" title="分词器相同的模型不止一个">
  同一种分词器常被多个模型复用，例如小米 MiMo 与 MiniCPM-V 复用 Qwen1 至 Qwen3 的分词器。有些中转站用 OpenAI 的开源分词库 tiktoken 在本地估算用量，估算出的计数同样对应 o200k_base 或 cl100k_base；判定为这两类且与所填模型不一致时，提示里会写明这种可能。两次对照请求的计数不同时，页面提示上游加入了长度会变化的隐藏内容（例如系统提示词），这次结果可能不准，可以重新探测一次。
</Callout>

## 没有分词器结果的情况

- 接口的响应里没有用量。有些中转站不转发上游的用量，这是接口本身的限制。
- 对照请求失败，或没有任何测试文本得到回答。探测中途失败时，已收到的计数照样并入。
- 回复经过手动编辑，或来自手动模式。
- 只有一两条有效回复。这时排名没有置信度，分词器结果只在详情里报告。

探测失败时，“分词器探测”卡的更多菜单和详情里的提示都提供“重新探测”。结果出现后重新探测成功，新的分词器结果直接并入当前结果，不需要重新取样。

## 导出

结果页更多菜单里的“导出 JSON”会带上每个候选的数字指纹置信度和分词器一致性，并附每个请求的计数。文件不含接口地址和 API Key。
