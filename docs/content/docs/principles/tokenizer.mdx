目标是用尽量少的短请求判断接口背后用的是哪一种分词器（模型把文字切成 token 的规则），再把这个判断并入数字指纹的置信度。数字指纹比较的是模型的输出偏好；分词器探测比较的是上游计算 token 的方式，它只需要接口在响应的用量（`usage`）中报告输入 token 数，与模型怎么回答无关。只要计数来自上游真实的分词器，上游改写回复也不影响结果。

## 差分计数

每个请求只含一条用户消息：固定前缀 $P$、测试文本 $t_j$、固定后缀 $S$。前缀是 `Reply with OK.\n<<<\n`，后缀是 `\n>>>`：前缀以非空白字符开头、后缀以非空白字符结尾，聊天模板裁掉首尾空白也不影响计数。对照请求只发 $P + S$。于是

$$
x_j - x_0 = \operatorname{count}(P\,t_j\,S) - \operatorname{count}(P\,S)
$$

聊天模板、注入的系统提示和特殊 token 这些隐藏内容在差值中抵消。不同协议读取不同的字段：Chat Completions 用 `prompt_tokens`，Responses 用 `input_tokens`，Messages 用 `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`。流式响应从带用量的事件中读取：Chat Completions 请求会附带 `stream_options.include_usage`，Messages 读 `message_start` 与 `message_delta`，Responses 读 `response.completed`。

## 分词器库

分词器库 `data/tokenizer_bank.json` 由分词器归档工具 llm-tokenizer-fingerprint 离线生成，对每个开源分词器算出同一个差值：

```mermaid
flowchart LR
    A["290 个开源分词器"] --> B["280 条候选文本<br/>逐一计算差值"]
    B --> C["计数完全相同的<br/>归为一类"]
    C --> D["同一谱系下只差<br/>少数文本的再合并"]
    D --> E["62 类"]
    E --> F["贪心挑选：尽量让每两类<br/>被 3 条测试文本区分"]
    F --> G["72 条测试文本"]
```

同一谱系合并后，类内成员在个别测试文本上的不同计数保留为 `alternatives`，判定时任一取值都算吻合。72 条测试文本覆盖中日韩文字、印度诸文字、东南亚文字、西里尔、阿拉伯、希伯来、希腊、亚美尼亚与格鲁吉亚文字，以及拉丁文本、代码、空白、符号、emoji 和结构化文本。

## 后验概率 [#posterior]

后验概率指看完全部计数后，每种假设的可信程度。假设分三种：

| 假设 | 先验 | 含义 |
| --- | --- | --- |
| 已收录的某一类 | 0.8 | 上游使用该类分词器，偏差只来自少见的测量误差 |
| 与某类相近的未收录分词器 | 0.1 | 相当一部分测试文本的计数与该类不同 |
| 与所有类都无关的分词器 | 0.1 | 每条测试文本的差值服从所有类的平滑分布 |

窄的一段对应精确吻合，宽的一段吸收偶发的偏差，下限让一次异常最多扣除有限的证据。每条测试文本的残差 $r$（实测差值与该类最近的允许取值之差）服从带下限的两段离散拉普拉斯混合：

$$
\ell(r) = \log\bigl((1-\rho)\,g_{0.02}(r) + \rho\,g_{0.85}(r) + 10^{-6}\bigr), \qquad g_p(r) = \frac{1-p}{1+p}\,p^{\lvert r\rvert}
$$

污染率 $\rho$ 在一组取值上求边缘：已收录类取 0.02、0.06、0.15，相近分词器取 0.2、0.4、0.7。隐藏内容的长度在对照请求附近 ±3 个 token 的窗口上求边缘；对照请求本身直接观测隐藏内容，使用固定的污染率。

## 挑选测试文本 [#selection]

每一批挑选最能分开“还分不清的候选”的测试文本，准则是成对 Bhattacharyya 上界：

$$
F(S) = \sum_{a<b} \sqrt{w_a w_b}\,\Bigl(1 - \prod_{j \in S} \mathrm{BC}_j(a, b)\Bigr)
$$

其中 $w$ 是当前后验概率，$\mathrm{BC}_j(a,b)$ 是两类在测试文本 $j$ 上预测分布的 Bhattacharyya 系数，也就是两者预测的重叠程度，重叠越大，这条测试文本越分不开它们。这个量是 MAP 错误率（取概率最大的一类作结论时判错的概率）的上界，且单调次模，也就是每多选一条收益只会递减，所以逐条贪心挑选有保证：贪心批次不差于最优批次的 $1 - 1/e$；计数精确时，它退化为等价类边切割（EC²，把还分不清的类一对一对切开）。

停止条件：

- 至少回答了 4 条测试文本后，某一类或“未收录”的后验概率达到 99%；
- 或者最佳批次对上界的改进小于 $10^{-4}$；
- 或者达到测试文本上限（默认 20 条）。

最后再发一次对照请求；两次计数不同说明上游加入了长度会变化的隐藏内容，结果会带上提示。

## 判定与核对

| 判定 | 条件 | 报告的概率 |
| --- | --- | --- |
| `exact` 完全一致 | 某一类的后验概率不低于“未收录”的总和 | 恰好是该类的概率 |
| `related` 未收录 · 最接近 | 某类的相近分词器的后验概率不低于“无关分词器” | 是该类相近分词器的概率 |
| `unknown` 未收录的分词器 | 其余情况 | 任一未收录分词器的概率 |

所填模型名去掉供应商前缀和 `:` 后缀后，先按[厂商型号映射](#api-models)匹配，再按各类的别名匹配。核对的概率是上游使用该型号对应的类（恰好是该类或其相近分词器）的后验概率；映射为 `null` 的型号（厂商没有公开分词器）改用“未收录”的后验概率。概率不低于 0.9 为一致，不高于 0.1 为不一致，其余为还不能确定。映射和别名都不匹配的型号无法核对。

## 并入置信度 [#fusion]

给定模型时，模型选数字的偏好与上游计算 token 的方式互不影响，于是分词器结果可以按贝叶斯规则乘进数字指纹。每个候选 $m$ 的校准后验概率乘上

$$
(1-\varepsilon)\,\mathrm{BF}(m) + \varepsilon,\qquad \mathrm{BF}(m) = \frac{P(H_m \mid \text{counts})}{P(H_m)}
$$

再归一化，候选按结果重新排序。$H_m$ 是与 $m$ 兼容的分词器假设：$m$ 对应的类及其未收录的近亲；厂商没有公开分词器时是“未收录”。$\mathrm{BF}(m)$ 是这组假设的后验与先验之比，也就是它相对计数边缘分布的贝叶斯因子；探测前后验等于先验，所有因子都是 1。

$\varepsilon = 0.1$ 是 Huber $\varepsilon$ 污染份额，对应用量不按模型的分词器计数的情况，例如中转站在本地估算。它限定单凭计数能把排名推动多远：一类的因子最大约为 62.1，最小为 0.1，两个候选的概率比最多改变约 600 倍。

参考库中本工具不知道分词器的型号，按同一家族其他型号的分词器计算：以 0.8 的概率沿用它们的类，否则视为未收录的分词器。整个家族都不知道分词器时，因子为 1。显示的一致性按沿用的类判定。

以下情况不改变排名，分词器结果只作报告：

- 只有一两条样本，排名没有校准概率；
- 自定义参考库与检测器不匹配；
- 只有对照请求得到回答，没有任何测试文本的计数。

## 评估 [#evaluation]

在 62 类分词器上离线模拟上游（隐藏内容的长度随机，`eps05` 表示每条测试文本以 5% 的概率偏离 1–2 个 token，`eps15` 表示以 15% 的概率偏离 1–4 个 token）：

| 设置 | 第一名正确 | 平均请求数 |
| --- | --- | --- |
| 逐个发送，无噪声 | 62 / 62 | 约 11 |
| 逐个发送，`eps05` | 62 / 62 | 未统计 |
| 逐个发送，`eps15` | 61 / 62 | 未统计 |
| 同时 4 个，无噪声 | 62 / 62 | 约 13 |

置信度在 0.9–1 区间的平均值为 0.987，实际正确率为 1.000。

逐一把某一类从分词器库中移除、再用它的计数探测（留一类评估），有 8 / 62 次被判为另一个已收录的类。这些都是衍生或扩展关系的分词器对，例如 cl100k_base 与 StableLM 2、GPT-2 与 CodeGen、Llama 3 与千帆 VL、Llama 2 与 OpenHathi：扩展版本在测试文本上与原分词器几乎一致，只看计数无法区分。

并入置信度的效果用参考库的真实回答评估：每个模型取 3 条回答，配上三种计数，比较并入前后第一名的正确率。完整回答的数字指纹几乎总是对的，所以把每条回答截到前 100 或 80 个整数，削弱数字证据：

| 计数来源 | 100 个整数 | 80 个整数 |
| --- | --- | --- |
| 上游真实的分词器（39 轮） | 0.974 → 1.000 | 0.974 → 1.000 |
| 中转站用 cl100k_base 估算（51 轮） | 0.980 → 0.980 | 0.980 → 0.980 |
| 与所有类都无关的分词器（51 轮） | 0.980 → 0.980 | 0.980 → 0.961 |

计数来自真实分词器时，正确模型的平均置信度从 0.970 升到 0.991（100 个整数），从 0.946 升到 0.979（80 个整数）。唯一被纠正的是 kimi-k3：数字指纹把它排在 qwen3.8-max 之后，并入 Kimi 的分词器后排到第一。中转站估算的计数没有造成误判；把所有模型的计数都换成无关分词器这种不利情况下，80 个整数时 51 轮里有 1 轮第一名改变。

## 局限

- 分词器一致只说明分词器相同。同一种分词器常被多个模型复用，例如小米 MiMo 与 MiniCPM-V 复用 Qwen2 到 Qwen3 的分词器。
- 中转站若用 tiktoken 在本地估算用量，也会测成 o200k_base 或 cl100k_base。
- 未收录但由已收录分词器扩展而来的分词器，可能被判为原分词器，见上面的留一类评估。
- 本工具不知道分词器的型号沿用家族的分词器，并留出 0.2 的概率给新分词器；这让它们的因子比同家族已知型号低约 20%，数字指纹几乎打平时，顺序可能因此改变。
- 上游不报告用量，或报告的计数经过修改时，无法探测。
