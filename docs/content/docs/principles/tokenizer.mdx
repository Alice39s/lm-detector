整数指纹比较的是模型的输出偏好；词表探测比较的是上游计算 token 的方式。它只需要接口在响应的 usage 中报告输入 token 数，与模型怎么回答无关，因此即使上游改写了回复，只要计数来自真实的分词器，结果就不受影响。

## 差分计数

每个请求只含一条用户消息：固定前缀 $P$、探针文本 $t_j$、固定后缀 $S$。前缀是 `Reply with OK.\n<<<\n`，后缀是 `\n>>>`：前缀以非空白字符开头、后缀以非空白字符结尾，聊天模板裁掉首尾空白也不影响计数。基线请求只发 $P + S$。于是

$$
x_j - x_0 = \operatorname{count}(P\,t_j\,S) - \operatorname{count}(P\,S)
$$

聊天模板、注入的系统提示和特殊 token 这些固定开销在差值中抵消。不同协议读取不同的字段：Chat Completions 用 `prompt_tokens`，Responses 用 `input_tokens`，Messages 用 `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`。流式响应从带 usage 的事件中读取：Chat Completions 请求会附带 `stream_options.include_usage`，Messages 读 `message_start` 与 `message_delta`，Responses 读 `response.completed`。

## 词表库

词表库 `data/tokenizer_bank.json` 由词表归档工具 llm-tokenizer-fingerprint 离线生成，对每个开源词表算出同一个差值：

```mermaid
flowchart LR
    A["290 个开源词表"] --> B["280 条候选文本<br/>逐一计算差值"]
    B --> C["计数完全相同的<br/>归为行为类"]
    C --> D["同一谱系下只差<br/>少数文本的再合并"]
    D --> E["62 类"]
    E --> F["贪心选探针：每两类<br/>至少被 3 条区分"]
    F --> G["72 条探针"]
```

同一谱系合并后，类内成员在个别探针上的不同计数保留为 `alternatives`，判定时任一取值都算吻合。72 条探针覆盖中日韩文字、印度诸文字、东南亚文字、西里尔、阿拉伯、希伯来、希腊、亚美尼亚与格鲁吉亚文字，以及拉丁文本、代码、空白、符号、emoji 和结构化文本。

## 后验 [#posterior]

后验分三类假设：

| 假设 | 先验 | 含义 |
| --- | --- | --- |
| 已收录的某一类 | 0.8 | 上游使用该类词表，偏差只来自少见的测量误差 |
| 与某类相近的未收录词表 | 0.1 | 相当一部分探针与该类不同 |
| 与所有类都无关的词表 | 0.1 | 每条探针的差值服从所有类的平滑分布 |

每条探针的残差 $r$（实测差值与该类最近的允许取值之差）服从带下限的两段离散拉普拉斯混合：

$$
\ell(r) = \log\bigl((1-\rho)\,g_{0.02}(r) + \rho\,g_{0.85}(r) + 10^{-6}\bigr), \qquad g_p(r) = \frac{1-p}{1+p}\,p^{\lvert r\rvert}
$$

窄的一段对应精确吻合，宽的一段吸收偶发的偏差，下限让一次异常最多扣除有限的证据。污染率 $\rho$ 不固定，而是在一组取值上求边缘：已收录类取 0.02、0.06、0.15，相近词表取 0.2、0.4、0.7。隐藏开销在基线附近 ±3 个 token 的窗口上求边缘；基线本身直接观测开销，使用固定的污染率。

## 挑选探针 [#selection]

下一批探针按成对 Bhattacharyya 上界选择：

$$
F(S) = \sum_{a<b} \sqrt{w_a w_b}\,\Bigl(1 - \prod_{j \in S} \mathrm{BC}_j(a, b)\Bigr)
$$

其中 $w$ 是当前后验，$\mathrm{BC}_j(a,b)$ 是两类在探针 $j$ 上预测分布的 Bhattacharyya 系数。它是 MAP 错误率的上界，且单调次模，贪心批次不差于最优批次的 $1 - 1/e$；计数精确时退化为等价类边切割（EC²）。只在后验最高的 24 类之间规划，第一批的计划会被缓存。

停止条件：

- 至少回答了 4 条探针后，某一类或“未收录”的后验达到 99%；
- 或者最佳批次对上界的改进小于 $10^{-4}$；
- 或者达到探针上限（默认 20 条）。

最后再测一次基线；两次基线不同说明上游加入了会变化的隐藏内容，结果会带上提示。

## 判定与核对

| 判定 | 条件 | 报告的概率 |
| --- | --- | --- |
| `exact` 完全一致 | 某一类的后验不低于“未收录”的总和 | 恰好是该类的概率 |
| `related` 未收录 · 最接近 | 某类的相近词表后验不低于“无关词表” | 是该类相近词表的概率 |
| `unknown` 未收录的词表 | 其余情况 | 任一未收录词表的概率 |

所填模型名去掉供应商前缀和 `:` 后缀后，先按[第一方型号映射](#api-models)匹配，再按各类登记的别名匹配。核对的概率是上游使用登记的类（恰好是该类或其相近词表）的后验；映射为 `null` 的型号（厂商没有公开词表）改用“未收录”的后验。概率不低于 0.9 为一致，不高于 0.1 为不一致，其余为尚不能确定。映射和别名都不匹配的型号只显示词表判定。

## 评估 [#evaluation]

在 62 类词表上离线模拟上游（隐藏开销随机，`eps05` 表示每条探针以 5% 的概率偏离 1–2 个 token，`eps15` 表示以 15% 的概率偏离 1–4 个 token）：

| 设置 | 第一名正确 | 平均请求数 |
| --- | --- | --- |
| 逐个发送，无噪声 | 62 / 62 | 约 11 |
| 逐个发送，`eps05` | 62 / 62 | — |
| 逐个发送，`eps15` | 61 / 62 | — |
| 同时 4 个，无噪声 | 62 / 62 | 约 13 |

置信度在 0.9–1 区间的平均值为 0.987，实际正确率为 1.000，略偏保守。

逐一把某一类从词表库中移除、再用它的计数探测（留一类评估），有 8 / 62 次被判为另一个已收录的类。这些都是衍生或扩展关系的词表对，例如 cl100k_base 与 StableLM 2、GPT-2 与 CodeGen、Llama 3 与千帆 VL、Llama 2 与 OpenHathi：扩展词表在探针上与原词表几乎一致，只看计数无法区分。

## 局限

- 词表一致只说明分词器相同。同一词表常被多个模型复用，例如小米 MiMo 与 MiniCPM-V 复用 Qwen2–Qwen3 词表。
- 中转站若用 tiktoken 在本地估算 usage，也会测成 o200k_base 或 cl100k_base。
- 未收录但由已收录词表扩展而来的词表，可能被判为原词表，见上面的留一类评估。
- 上游不报告 usage，或报告的计数经过修改时，无法探测。
