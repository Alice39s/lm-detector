# 第二阶段：跨来源的全库开发选择

第一阶段的 30 个组特征、30 个序列特征、11 个来源方案及 35 个组合没有超过原融合的 580/636。第一阶段的候选和结果保持原样。本阶段在打开固定 104 组回归数据或新增 API 回答之前声明。

本阶段比较来源稳健性。只看原 636 组会忽略已经发现的采集渠道差异，因此使用 636 个正式开发组及两个已转为开发的 40 组配对资料。所有旧配对资料的第一次验证结果和原 manifest 保留，不能重新称为独立验证。固定 holdout 仍不得加入任何训练或校准。

主开发指标为 53 标签等权的 Macro Top-1；每个标签内，将实际采集来源的命中率等权平均，再对标签平均。来源由参考记录的 channel 及历史 API endpoint 确定；同一实际来源的多个开发批次合并计算，不能因为增加批次而增加权重。推断只接收整数序列，不接收来源、速度、模型字符串或请求参数。先按此指标选择，再按相同加权方式的 MRR，最后按固定配置编号选择。原 636 组的命中、来源内表现及跨来源诊断必须同时报告。

先按此指标重新比较已有的 11 个来源候选，另保存选择记录，不能覆盖第一阶段 selection。若增加均衡来源的三回答组分类器，只使用已选定的 751 维位置输入，比较均值和均值加组内标准差及回答间距离，以及三个 LDA shrinkage（0.15、0.5、0.85）。六个头与原冻结融合的等权组合再构成六项，共 12 项；加上原冻结融合对照，共 13 项。运行前保存完整计划。

每个标签的来源内生成固定 64 个三元组，成员不重复，覆盖当前折全部可用回答；不混用三元组内的来源。每个标签及其内部来源等权拟合尺度、中心和协方差。参考环境留出及配对轮次留出沿用第一阶段的文本、整数序列、题号和环境去重规则，并同时留出同一配对轮次的两个模型。

先保存所有候选的开发分数，再按上述规则确定本阶段唯一候选，冻结全部源码、输入、权重与普通字典模型。随后检查已见的全库回归资料；只要改变候选，该资料就只能称为回归检查。另行采集的 v2 盲测必须绑定冻结候选，采集、重试和首个合格回答的接纳均不读取识别分数。本阶段冻结之后不再根据回归或盲测结果更换算法。

目前只有三个参考标签拥有多来源训练资料，两个标签拥有额外来源的留出组。该指标覆盖全部 53 标签，但跨来源的证据范围有限，不能声称已经证明所有模型在所有渠道上的识别性能。
