# 冻结通用排名器的产品化可行性

冻结的通用方案可以导出 JSON，并用 TypeScript/Bun 实现等价推理。现有 `shared-detector-v1` 不能直接消费这些新参数，需要一个可选的排名扩展。不能把研究温度直接写入现有校准头，也不能仅修改排名后继续沿用旧置信度绑定。

本次只读取此前冻结的参考库 CV 选择、模型和推理代码。没有读取本轮新增固定测试集结果，没有重新挑选参数或按 Astra/Sol 结果选择方法。

## 固定选择

最优方案由全 53 标签的 636 个三回答组选择：50% 通用前两名重排 + 50% `all_sequence_lda_s0.15`。Dense SVM 权重为零，不需要导入产品。该组合的参考库开发命中为 580/636；原排名器为 564/636。组 Top-3 为 636/636。

重排配置固定为 `frequency_shrink0.3_gate0.25`。每组由原排名器选择前两名，再用对应两类的收缩协方差线性判别头判断是否交换这两个排名分数。交换只改变顺序，不增加原分数幅度。全部 1,378 个标签对采用相同规则，不包含模型名称特判。

序列位置分类器使用四个特征块：355 维 Hellinger 频率、74 维现有顺序分块、102 维相对位置核矩、220 维相邻/滞后统计。权重固定为 0.6/0.15/0.125/0.125，总维数 751；LDA 收缩为 0.15。

参考库参数与组合都在这些 CV 折上选择，580/636 是开发估计。该组合对 Astra/Sol 的参考库命中只有 15/24；不能据此宣称已经高置信区分两者。研究推理脚本的 `beta=4.778034578749429` 也只表示开发参考库上的 53 标签闭集温度。

## 最小推理实现

产品只需要普通数组运算，不需要在浏览器加载 Python、SciPy 或 scikit-learn，也不需要在查询时求协方差逆矩阵。

1. 保留现有原排名器，得到原始组分数 `base`。
2. 从 `base` 选前两名，按标签索引排序查找 JSON 中的局部头。只有原分数差不超过 0.25 时，使用该头的缩放、分块归一化、429 维系数和三回答均值判断是否交换前两名。
3. 复用现有频率与顺序分块函数。新增 102 维相对位置核矩和 220 维序列统计，按 JSON 的逐块均值、尺度、权重归一化。
4. 对每条回答计算 53 个线性位置分数，先在标签之间标准化，再对三条回答取均值。
5. 将重排分数与位置组分数分别在全库标签间标准化，然后各乘 0.5 相加。

数值顺序必须与 Python 一致：先逐回答标准化位置分数，再平均；最后才对组分数标准化。局部门限使用原排名器的分数，不使用最后标准化后的分数。相对位置核的展平顺序、平滑常数、总体标准差和稳定排序也必须一致。

新增查询计算量主要是三次 `53 × 751` 的矩阵乘法，约 119,409 次乘加；局部头最多增加 `3 × 429` 次乘加。相对位置核计算约 `3 × n × 24` 次指数运算，序列统计对各滞后线性扫描。所有标签对的拟合留在离线导出阶段。

最小产品改动预计包括：一个 TypeScript 数学模块、一个明确类型的可选 JSON 扩展字段，以及离线导出的固定配置入口。约 200–300 行新增推理代码即可表达特征与组合；实际行数取决于复用现有向量函数的程度。这是实现规模估计，不是已经完成的 TS/Python 一致性证明。产品构建不能依赖 `projects/` 之外的研究代码，必要的固定方法应放入 `projects/offline/`，研究导出脚本只作为可审查原型。

## 核验器和置信度

当前核验器的六个有效输入包括候选排名差，全部 `[0,1,2,3,4,5]` 都进入模型。若把融合排名直接代入这个旧特征，核验器输入分布会变化，不能只替换返回排名就声称核验器和置信度仍有效。

最小可审查路径是让旧核验器继续使用原排名器的差值特征，并单独返回新的融合排名。这样旧核验计算按原定义执行；排名与核验分歧仍可展示。复合排名器应有新的模型指纹，绑定参考库、标签顺序、全部扩展参数和固定组合权重。

新的排名温度必须由同一复合排名器的参考库跨折分数拟合，并通过现有离线安装流程要求的嵌套环境校准。旧 `base_sha256`/校准绑定不能沿用。新校准完成前，排名可以作为候选顺序输出，置信度应保持不可用；不能通过改写显示阈值或复制研究温度来制造高置信。

对一条或两条回答，保留现有部分样本排名行为。被冻结的正式比较和温度只使用三回答组，不应把它直接解释为一回答的置信度。

## 建议

如果本轮产品目标是交付已冻结的全库排名改进，这个方案具有可实现的 JSON/TS 路径。优先保留精确方法和明确的模型版本，再完成只用参考库的校准与语言间推理一致性核对。新增验证集可以检查冻结方案的回归，但不能继续用于挑权重。

新增 16.5 MB gzip 是实质成本。如果当前网页无法接受这一成本，保留研究方案也合理；不应为了看起来上线了改进而静默删掉未知标签对，或者在查询时加入一套新的矩阵求解器。即使产品采用这个通用排名器，也应分别说明全库准确率改进和 Astra/Sol 尚未解决的区分问题。
